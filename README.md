# Thesis-RL

Offline reinforcement learning for prescriptive process monitoring on the SimBank simulator.

## What this is about

This thesis investigates how well different offline RL methods can learn to prescribe interventions in a sequential business process when only historical (logged) data is available. The setting is the SimBank loan application process, which has three sequential decision points: choosing the procedure, deciding whether to contact headquarters, and setting the interest rate level.

The research question is whether offline RL methods can recover (or exceed) the performance of the existing rule-based bank policy by learning purely from logged interventions, without any further interaction with the live process. Two data conditions are studied. The RCT condition reflects an idealized world where past actions were taken uniformly at random, so the offline data covers the action space. The CONF condition is more realistic: the data was generated by a biased policy, so off-policy estimation has to deal with confounding.

Nine methods are compared under a single, standardized evaluation protocol. They span clustering plus tabular Q-iteration (kmeans), sequence-based deep Q-networks (lstm, rims), conservative Q-learning variants (singleModelCQL, multiModelCQL), and several causal-reward DQN approaches that combine an S-learner with a downstream DQN (procause_econml, procause_lstm, lstm_dqn_dragonnet, lstm_dqn_tabpfn). For every method the same four-file structure is used so that data generation, training, and evaluation are directly comparable across approaches.

Two experimental dimensions are explored on top of the basic comparison. The first, run via `run_all_steps.py`, varies how many of the three intervention points are RL-controlled in cumulative order (the first one only, the first two, or all three), with the remaining points falling back to the bank policy. This isolates the marginal contribution of each successive intervention. The second, run via `run_intervention_combos.py`, evaluates every non-empty subset of the three intervention points (seven subsets in total) by reusing the steps=3-trained models and wrapping them in a `SubsetPolicy` that defers to the bank policy for non-active interventions. This answers which intervention combinations matter most without requiring any retraining.

## Method porting standard

Every method directory has exactly four files in this order:

| File | Role |
|---|---|
| `generate_data.py` | Generate raw SimBank cases (delegates to `shared/`) |
| `convert_data.py`  | Extract `(s, a, r, s', terminal, intervention)` transitions |
| `train.py`         | Train the policy or Q-function only |
| `evaluate.py`      | Evaluate via `shared.evaluate_policy` against Bank and Random baselines |

CLI arguments, file naming, state representation, and result-dict keys are standardized. See `METHOD_TECHNICAL_DETAILS.md` for the full specification.

## Experiment scripts

### Cumulative steps (marginal contribution)

```bash
python run_all_steps.py                         # all methods, all steps {1,2,3}, RCT and CONF
python run_all_steps.py --methods kmeans lstm   # subset of methods
python run_all_steps.py --steps 3               # 3-step only
python run_all_steps.py --no_confounded         # RCT only
```

`--steps N` controls the first N interventions with the trained policy and falls back to the bank policy for the rest. Output is written to `results/all_results.json`.

### Intervention subsets (arbitrary combinations)

```bash
python -u run_intervention_combos.py                       # all 9 methods, all 7 subsets, RCT and CONF
python -u run_intervention_combos.py --methods lstm rims   # subset of methods
```

Reuses the steps=3-trained models with no retraining. `SubsetPolicy` falls back to the bank policy for non-active interventions. Output is written to `results/intervention_combos_results.json`. See `INTERVENTION_COMBOS.md` for details.

### Figures

```bash
python plot_results.py                          # writes results/figures/fig*.{pdf,png}
```

## Shared evaluation protocol

The same protocol is used across every method and every script:

* 5 standard seeds: `[42, 123, 456, 789, 1024]`
* Evaluation seed convention: `99{train_seed}` (so train seed `42` evaluates with seed `9942`)
* Default test set: 1000 episodes per evaluation
* Default training set: `n_cases=10000`
* Two data conditions, **RCT** (randomized data collection) and **CONF** (confounded, `--delta 0.95`)
* Three intervention points with `N_ACTIONS = [2, 2, 3]`:
  * Int 0: `choose_procedure` (standard / priority)
  * Int 1: `contact_HQ` (contact / skip)
  * Int 2: `set_ir_3_levels` (7% / 8% / 9%)
